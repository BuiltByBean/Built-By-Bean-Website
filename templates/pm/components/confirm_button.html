{# A destructive action that asks in place, instead of through confirm(). The browser's confirm() is an OS dialog: system grey, system font, its own buttons, blind to the theme - the same chrome problem the select and checkbox components exist to escape, and the one place it appears at the exact moment somebody is deleting something. It also blocks the whole page and reads as a browser warning rather than as part of the app. Pressed once, the button turns into its own question with the answer beside it. Clicking outside backs out, so a mis-tap costs nothing. label the resting label, e.g. "Delete". For an icon button, omit it and pass the icon markup in a {% call %} block instead - the caller's content becomes the resting button, so a row of icons keeps its shape until asked. question what the armed button says, e.g. "Delete it?" btn_class classes for the resting button, so each caller keeps whatever it already looked like tone 'danger' (default) or 'brand' for the armed button wrap_class classes for the wrapper, for a caller that needs the control to fill its column The armed button is the only submit, and it is disabled until armed, so a stray Enter in the form cannot fire the destructive path. #} {% macro confirm_button(label='', question='Sure?', btn_class='', tone='danger', wrap_class='') %} {% endmacro %}
